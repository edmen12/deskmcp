# Real Windows virtual Desktop 2 — Computer Use / Agent Desktop lease bridge

**Status: source-only candidate, NOT an exposed MCP route. Isolation release gate RED.** Written 2026-10-09 after the owner's reproduced WinApp `ui set-value` foreground theft. Production DeskMCP 0.9.23 and `main` are not modified.

## Why this bridge exists

The existing production `desktop_ui_action` mainly executes UIA via bundled WinApp in a lease-scoped **private Win32 Desktop Object**. The user instead wants GUI apps on the same physical Windows session's **virtual Desktop 2**, with zero forced switches away from Desktop 1. These are different OS isolation mechanisms. A Windows virtual desktop does not provide a separate global keyboard/mouse stream, and a WinApp UIA action can activate the target WPF HWND even when the verb is conceptually background-safe.

One live A/B comparison identified the triggering call path: `winapp.exe ui set-value` on unprotected WPF Desktop 2 window. The foreground target PID and HWND were observed approximately 118 ms before `Desktop1→Desktop2`; passive VDA notifications confirmed the switch. Repro evidence: `test-area/desktop2-incident-trace/findings-20261009.md`. A former WinApp CLI run of one protected WPF fixture did not reproduce foreground theft; **that was not a universal guarantee**.

**Newer and more important real failure (2026-10-09 ~06:03 MYT):** The full candidate virtual Desktop2 lease→passive window inventory→observer arm→guarded native UIA metadata snapshot successfully recognized a protected WPF window and its TextBox/ScrollViewer. On the *first direct .NET UIA `ValuePattern.SetValue`*, the WPF HWND **became system foreground while the human remained on Desktop1**. `TARGET_FOREGROUND_EARLY_ABORT` latched; there were **no actual VDA virtual-desktop change notifications or polling-detected switches in this run**, but the WPF root received activation/focus messages and text was altered, with an additional unexpected edit. The monitor can detect but cannot undo the first focus/input interference. Full evidence: `test-area/desktop2-real-acceptance/incident-20261009-direct-uia-focus-steal.md`.

**Containment:** direct UIA `set-value` has been quarantined at both TypeScript entry and native C# policy boundary, removed from native executable mutation implementation. The one-shot GUI reproducer is also hard-quarantined. This preserves legitimate future app-specific transports, while refusing a proven unsafe one. Production remains unchanged and release status remains RED.

## Implemented source-only linkage

- `src/desktop2-computer-use-candidate.ts`: issues lease-bound one-time window capabilities from passive inventory, then **separate one-time semantic observation IDs only after a guarded native UIA metadata snapshot**. A raw Computer Use observation ID cannot authorize a guessed automationId. Each action must match the snapshot's canSetValue/canScrollTopBottom, window_id, lease, and **exact observer ready-file path**; mismatches burn the permit. Shares existing `ComputerWindowRegistry`, `ComputerObservationRegistry` and `ComputerUseCoordinator`. Rejects stale/reused observation IDs, HWND reuse / process/class mismatch and Agent safety HUD. Advances observation generation before native UIA can mutate the app.
- `src/desktop2-direct-uia-lease.ts`: checks `AgentDesktopManager.assertLease` (including live HUD heartbeat), `assertWindowOnLease`, current Desktop1, actual Desktop2's GUID and index, target not pinned/shared, and the same lease generation before/after helper invocation. Handles watcher `arm` and guarded metadata/semantic scrolling; **direct WPF/WinForms `ValuePattern.SetValue` has been quarantined after the observed foreground theft**, before any native invocation. An alternative non-foreground transport must be independently tested and connected for text editing. Binding `desktopNumber` may be absent on valid older configs; `control.desktopNumber` and native VDA real-time values must both equal 2.
- `Desktop2DirectUiaProcessInvoker`: invokes the standalone native helper through a bounded `execFile` without WinApp CLI, `shell:false`, Windows hidden process, per-request private temporary JSON file (removed on completion). Never includes the text value in errors.
- `test-area/desktop2-direct-uia/Program.cs`: native helper validates root HWND/PID, Desktop2 GUID, Desktop1 active, `WS_EX_NOACTIVATE` on mutations, observer identity/start timestamp, target HWND/PID watch, and latched tripwire. It refuses `invoke`/click/drag/system keyboard.
- `test-area/desktop2-switch-observer/Program.cs`: listens for actual desktop changes and monitored target foreground activation; cannot itself prevent an already queued OS switch. Target arming is done by native helper after verifying window identity and style; the manifest is published atomically.

### Candidate-only call sequence

1. Start a live Agent Desktop control lease for Desktop2 (the existing native HUD heartbeat must be valid).
2. Create a passive observer for this lease/window, `--observe-target`; it publishes a private ready file and a not-yet-created target-watch path. No user-desktop control.
3. Enumerate Desktop2 HWND/PID/process/class **passively** via `session.discoverWindows()`, without invoking WinApp or any UIA provider. This issues an initial lease-bound **window capability + one-time arm observation**.
4. Call `session.dispatch(phase='arm', windowId, computerObservationId)`. Native `--arm-target` checks lease/identity, `WS_EX_NOACTIVATE` and watcher, then atomically registers the exact target HWND/PID.
5. Call `session.snapshotWindow(windowId)`: only **after arming**, run bounded `--request inspect-tree` under the same activation guard and observer, enumerate up to 128 nodes/32 eligible controls, reject duplicate automationId or incomplete tree, and return **no text content**. It issues a fresh *semantic* observation token bound to window/lease/observer path and allowed action types.
6. `session.dispatch(phase='perform', action=scroll)` remains a **candidate only** under the same semantic token; scroll has not received separate live foreground-safety acceptance. **Do not execute direct `set_value`**: native and TS deny before the UIA provider, because the 06:03 live test demonstrated real foreground theft even with `WS_EX_NOACTIVATE`.
7. Any future validated *app-specific* editor transport must carry the same lease/window/monitor/semantic controls, verify app-side callbacks, and demonstrate no target foreground theft. No generic UIA keyboard/clipboard fallbacks.
8. On foreground theft, switch, lease loss or observer failure, reject new operations and keep monitoring until already-running native helpers have exited. Never auto-return to Desktop1.

## Release blockers (must not skip)

- **Implemented source-only native passive inventory:** `agent-desktop-host/Program.Inventory.cs` adds `list-virtual-windows --desktop-id <real Desktop2 GUID>`. Uses read-only `EnumWindows`, `GetWindowRect/Text/Class`, owner PID/process name and `IVirtualDesktopManager.GetWindowDesktopId/IsWindowOnCurrentVirtualDesktop`, rejects pinned/shared/current-Desktop1 windows and checks current desktop=1 before and after; no WinApp, focus, ShowWindow, virtual-desktop switching or input. `AgentDesktopNativeBridge.listVirtualWindows` and `src/desktop2-window-inventory.ts` validate the response and HUD-backed Agent lease and can serve the `listLiveWindowsPassively` dependency. The native helper compiled with 0 warnings, and a *real, read-only, no GUI launch* probe returned `WINDOW_COUNT=0`, `BEFORE_DESKTOP=1`, `AFTER_DESKTOP=1`. The subsequent protected WPF live test **did** enumerate one real Desktop2 window and issue an exact HWND/PID capability without triggering foreground activation at that step. This sample does not certify arbitrary third-party window enumeration; no production MCP endpoint is registered.
- **Observer/session live status:** `src/desktop2-observer-lifecycle.ts` starts the owned message-only hook with PID/start-time/lease/HUD verification and tripwire logging; readiness wait now defaults to 15s under measured ~580MB free-memory pressure, still fail-closes until ready. A **monitor-only real run PASSED** (ready in ~2417ms, owner Desktop1 before/after, no tripwire). In the later owned WPF live test, the observer armed and caught real target foreground theft **without a virtual desktop switch**, and the session stopped and released the Agent lease. Production lifecycle hooks remain unconnected.
- **Guarded semantic snapshot live status:** `DirectUia.SemanticSnapshot.cs` successfully inspected the real protected WPF Desktop2 window with a bounded ControlView subtree and returned `WpfEdit` and `WpfScroller` metadata under live observer/HWND/PID/lease checks. Snapshot itself raised **no observed foreground event**. The subsequent separate direct UIA `set-value` operation **did** steal foreground and mutate app text; therefore a positive snapshot **does not** certify a safe mutation transport. Direct UIA ValuePattern mutation is now quarantined at C# and TS boundaries.
- `WS_EX_NOACTIVATE` is not a universal programmatic focus barrier: **the live protected WPF target still received `WM_ACTIVATE` and focus while the owner stayed Desktop1**. Target foreground activation, keyboard contamination and desktop switching are distinct release-blocking events. App-specific adapters need independent validation.
- **Still RED:** no approved no-foreground text-editing route for arbitrary WPF/WinUI/Electron; semantic scroll is unverified live; no general third-party Computer Use release. Candidate code is not registered on production MCP. `92/92` targeted TypeScript tests and `11/11` native source safety contracts pass, but these do not override the real focus-theft incident.
- No automatic Windows virtual-desktop switch, global SendInput, shared clipboard fallback, VM, Win32 Desktop Object substitution, install, restart or production update.

```text
node --test --test-concurrency=1 dist/tests/desktop2-computer-use-session.test.js dist/tests/desktop2-observer-lifecycle.test.js dist/tests/desktop2-window-inventory.test.js dist/tests/desktop2-computer-use-candidate.test.js dist/tests/desktop2-direct-uia-lease.test.js dist/tests/desktop2-background-input.test.js dist/tests/desktop2-handoff.test.js dist/tests/computer-use-safety.test.js
```

Result: **92 tests, 92 PASS, 0 FAIL**. C# native source security contracts **11/11 PASS** with an explicit negative test confirming `set-value` rejects before the UIA provider. Real passive observer readiness/stop PASS. Real WPF window enumeration and guarded metadata snapshot PASS for the owned fixture; **the subsequent native ValuePattern mutation demonstrably stole focus** and has been quarantined. The virtual desktop did not switch in that last sample. The tests do not demonstrate general interference-free Computer Use.

**Delivery rule:** Leave production `desktop_ui_action` unchanged until the passive provider, observer lifecycle, real-window test and first-switch safety are demonstrably ready. Do not present this candidate as general Computer Use.

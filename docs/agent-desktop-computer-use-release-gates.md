# Agent Desktop / Computer Use — no-upgrade release gates (2026-10-08)

**Owner-confirmed requirement (2026-10-09):** Agent uses the **real local Windows virtual Desktop 2**, not a VM or hidden Win32 Desktop Object. **A brief Desktop 1 app appearance during startup is acceptable if the window is promptly moved to Desktop 2.** During **autonomous Computer Use**, Agent must NOT switch away from the owner's current desktop, steal their keyboard/mouse/focus, or fall back to global SendInput. A **deliberate and owner-aware human handoff** (account login, OTP, permission, manual action) may bring Desktop 2 into view; Agent must pause and must never forcibly return the owner to Desktop 1. Manual owner Desktop1/2 switching stays unrestricted. **No upgrade of installed 0.9.23 before completed E2E acceptance and owner approval.** See `docs/desktop2-operator-handoff-contract.md`.

## Unresolved: release blockers

- [ ] **Human inspection / takeover architecture:** Real Windows virtual Desktop2 placement and headful Chrome native window capture are now **proven** in local E2E. Historical Win32 Desktop Object is NOT acceptable as the visible Agent workspace. Owner **permits brief Desktop1 app appearance before prompt Desktop2 relocation**, but autonomous inputs must not switch or steal user focus. Need an actual lease-integrated UI action to request explicit handoff for login/OTP/permission, pause all Agent input, give human control on Desktop2, and resume only after human completion; never auto-return to Desktop1.
- [ ] **Full pointer and keyboard actions:** A generic click at coordinates, right/double click, mouse hover, drag/drop, wheel scrolling and arbitrary keyboard shortcuts are not supported on a non-current Win32 Desktop Object. Fail-closed is correct but not the user's desired full Computer Use. Find a genuinely independent interactive input channel and prove that all those actions reach only the Agent environment.
